# Customer Churn Prediction

A machine learning application that predicts customer churn using a trained scikit-learn pipeline. The project demonstrates an end-to-end ML workflow, including preprocessing, model evaluation, experiment tracking, automated testing, continuous integration, and deployment.

## Overview

This project uses the IBM Telco Customer Churn dataset to predict whether a customer is likely to discontinue a service.

Two classification models—Logistic Regression and Random Forest—were evaluated. Logistic Regression achieved **80.06% accuracy and a ROC-AUC of 0.845** on the evaluation dataset.

The selected model is exposed through a Gradio application that returns a churn prediction and estimated churn probability.

## Key Features

- **End-to-end ML pipeline:** Reusable preprocessing, feature engineering, model training, and evaluation.
- **Model comparison:** Evaluates Logistic Regression and Random Forest using multiple classification metrics.
- **Experiment tracking:** Uses MLflow to track model experiments and evaluation metrics.
- **Automated testing:** Includes eight pytest tests covering preprocessing and model training.
- **Continuous integration:** Uses GitHub Actions to automate test execution.
- **Interactive application:** Provides churn predictions and estimated probabilities through Gradio.
- **Deployment:** Hosted demo available on Hugging Face Spaces.

## Project Workflow

1. **Data preparation:** Load the customer churn dataset and prepare the features and target variable.
2. **Preprocessing:** Handle data types, transform features, and prepare data for model training.
3. **Model training:** Train Logistic Regression and Random Forest classifiers.
4. **Model evaluation:** Compare accuracy, precision, recall, F1 score, and ROC-AUC.
5. **Experiment tracking:** Record experiments and evaluation metrics using MLflow.
6. **Testing and CI:** Run automated tests with pytest and GitHub Actions.
7. **Inference:** Use the trained pipeline to generate predictions and churn probabilities.
8. **Deployment:** Serve predictions through a Gradio application hosted on Hugging Face Spaces.

## Production Deployment, CI/CD & Monitoring

For a production deployment, I would extend this project with a FastAPI inference service, Docker containerization, and a cloud hosting platform.

### CI/CD
- Use GitHub Actions to run automated tests and validate changes on every pull request.
- Build and publish a versioned Docker image after successful checks.
- Deploy to staging, run smoke tests, and promote to production after validation.
- Keep secrets in the deployment platform rather than in source code.

### Monitoring
- **Application:** Track API latency, request failures, traffic, and resource usage.
- **Data and model:** Monitor missing values, feature drift, prediction distributions, and model performance when actual outcomes become available.
- **Alerts and recovery:** Set alerts for failures or performance degradation, and maintain a rollback option for faulty releases.

### Production Considerations
Use input validation, authentication, secure configuration, and versioned model artifacts. Retrain only when evaluation on suitable data justifies a model update.

The current project demonstrates automated testing, GitHub Actions CI, MLflow experiment tracking, and hosted inference. Docker-based deployment, production CD, and operational monitoring are potential next steps.
